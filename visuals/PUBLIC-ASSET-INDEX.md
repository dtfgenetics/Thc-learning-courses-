## Delivery contract

- **Canonical public root:** `apps/web/public/assets/course1/`.
- **Approved production formats:** PNG, WebP, and JPEG/JPG only.
- **Canonical lesson data:** learner-facing image blocks must resolve to a governed raster entry in `visuals/ASSET-REGISTRY.json`.
- **Shared renderer overrides:** may only reference approved raster assets; regression tests reject SVG override paths.
- **Assessment stimuli:** production final-test images must use deployed PNG/WebP/JPEG assets and must never fall back to retired SVG compatibility files.
- **Accessibility:** lesson-specific alt text and captions remain controlled in course content; images must not be the sole carrier of required instructional meaning.
- **Responsive QA:** raster release still requires factual/copy review, mobile readability, public-path verification, and accessibility checks.
- **Google Drive:** may retain full-resolution masters, alternates, and review drafts, but Drive is not the public runtime dependency.
- **Change control:** the asset registry, canonical lesson mapping, and public file must stay synchronized. Do not update only one layer.

## Legacy SVG boundary

Legacy SVG records are retained only to preserve provenance and replacement history. Their registry lifecycle must remain `legacy-svg-compatibility-baseline` / retired where applicable, with an approved raster replacement recorded. Documentation or runtime code that describes those SVGs as the current production delivery contract is stale and should fail review.

The asset count is intentionally not capped. Add new raster visuals whenever they materially improve instruction, troubleshooting, practical preparation, accessibility, or learner transfer rather than simply increasing image count.
