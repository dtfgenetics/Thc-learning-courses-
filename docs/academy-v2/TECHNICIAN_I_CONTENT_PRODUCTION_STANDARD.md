# THC Academy V2 — Technician I Content Production Standard

## Purpose

This document defines what to create for each Cultivation Technician I task so multiple agents can produce material in parallel without drifting into inconsistent lesson formats or duplicating the encyclopedia.

The rule is simple:

**Canonical science lives in existing THC knowledge/lesson objects. Technician I content teaches how that science appears in routine cultivation work.**

## Standard package per job task

Each of the 12 Technician I task areas should ultimately include the following package.

### A. Job-practice unit

Target length: 20-45 minutes of focused instruction, excluding prerequisite science.

Required sections:
1. What the technician is responsible for
2. Why the task matters to crop/workplace quality
3. Prerequisite THC science links
4. Tools/equipment/materials used
5. Example SOP or work order
6. Step-by-step routine workflow
7. What to observe and record
8. Common mistakes
9. Stop/escalate conditions
10. Worked example
11. Guided practice
12. Knowledge check
13. Practical/simulation link
14. Documentation/portfolio link

### B. Visual package

Per task target:
- 1 primary process infographic
- 1 decision/escalation flowchart
- 1 annotated equipment/work-area visual
- 6-12 reference images or diagrams
- 2-4 correct-vs-incorrect comparison visuals

Every instructional visual should have:
- asset ID
- title
- purpose
- linked task/competency
- caption
- alt text
- source/evidence note where factual claims are shown

### C. Worked examples

Minimum 3 per task:
- routine successful example
- common-error example
- abnormal/escalation example

For data-heavy tasks such as environment, water and irrigation, target 5-8 worked examples.

### D. Guided practice

Minimum 3 practice activities per task.

Useful formats:
- arrange workflow steps
- mark hazards on an image
- annotate a crop photo
- complete missing record fields
- interpret a dashboard/table/chart
- choose an escalation action
- inspect a work order for errors
- compare two technician responses

### E. Scenario library

Minimum 6 scenarios per task.

Each scenario should contain:
- setting
- supplied observations/data
- task or decision
- expected reasoning
- best action
- plausible errors
- feedback

At least two scenarios per task should connect to another task area to prevent siloed learning.

### F. Question bank

Use the assessment-blueprint targets rather than a fixed equal count.

Every task bank should include:
- foundational questions
- applied questions
- visual/data interpretation
- workflow/order questions
- scenario questions
- documentation questions where relevant

Questions should be reusable across unit checks, practice and generated assessment forms based on purpose/status fields.

### G. Practical assessment

Each task must be represented in at least one of the six integrated practicals.

A practical brief needs:
- candidate instructions
- supplied materials/data/images
- observable behaviors
- rubric criteria
- expected artifacts
- evaluator notes
- simulation implementation notes if digital

### H. Portfolio evidence

Not every task needs a separate portfolio document, but the full Technician I portfolio should contain at least:
- crop observation/scouting report
- environment/irrigation shift log
- IPM scouting record
- propagation record
- work-order completion example
- harvest/postharvest traceability record
- deviation/handoff record
- one-shift capstone package

## Content-depth rule

Do not turn Technician I into an advanced manager/breeder curriculum.

Teach enough depth for the technician to:
- perform the routine task correctly
- notice meaningful abnormalities
- collect useful data
- protect plant/batch identity and quality
- document work
- know when to stop and escalate

Advanced diagnosis, system design, crop strategy and supervisory decisions belong primarily in Technician II, Specialist, Lead and Operations credentials.

## Writing style

Technician I content should be:
- plain enough for a motivated beginner
- technically correct
- visual and example-heavy
- specific about observable actions
- careful about context-dependent cultivation targets
- explicit about what is facility/SOP specific
- free of stoner folklore presented as science

Use cannabis terminology when needed, but also teach the horticulture/CEA vocabulary used by professional facilities.

## Reuse rule

Before creating a new science explanation:
1. search existing lessons
2. search encyclopedia/knowledge content
3. reuse or link the canonical object
4. create only the missing employment/application layer

This is how the Academy can become large without becoming repetitive.

## Agent handoff format

When Codex or Work completes one task area, the handoff should state:
- existing objects reused
- new objects created
- question count added
- visuals/assets requested or completed
- scenarios added
- practical mapping
- portfolio artifact mapping
- remaining gaps

This gives us a lightweight production ledger without creating another approval bureaucracy.
