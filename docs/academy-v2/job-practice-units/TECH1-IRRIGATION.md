# Technician I Job-Practice Unit — Irrigation Execution

**Task:** `TASK-CULT-IRRIGATION-001`  
**Target proficiency:** Operational  
**Primary competencies:** `COMP-WATER-001`, `COMP-ROOTZONE-001`  
**Prerequisite content:** `MOD-WATER-001`, `MOD-ROOTZONE-001`, `LESSON-ROOTZONE-DRYBACK-003`

## What the technician is responsible for

A Cultivation Technician I should be able to execute a supplied irrigation work order, verify that water or nutrient solution was actually delivered, observe the resulting root-zone condition, recognize obvious delivery problems, and document the task.

The technician is expected to:
- confirm crop/zone/work-order identity
- verify the correct irrigation source and routine setup
- execute manual or automated irrigation steps within authorization
- inspect for leaks, blocked emitters, disconnected lines or obvious uneven delivery
- recognize that dryback is a changing trajectory, not simply elapsed time
- observe whether the root zone appears unusually saturated or dry for the supplied context
- record event timing, volume/duration or other required fields
- preserve pH/EC/sample data when supplied
- avoid changing irrigation strategy beyond Technician I authority
- escalate delivery failures, abnormal dryback or equipment problems

Technician I is not expected to design crop-steering strategy or independently program complex fertigation systems.

## Before irrigation

Confirm:
- room/zone/crop identity
- work-order/SOP
- irrigation source/feed tank
- scheduled event/time
- required volume/duration or system command
- correct valves/zones
- any hold/deviation status
- measurement requirements

A correct irrigation event delivered to the wrong zone is still an incorrect event.

## Routine irrigation workflow

### 1. Inspect the delivery area

Check for:
- disconnected tubing
- obvious leaks
- pinched lines
- blocked or damaged emitters
- standing water
- containers moved away from emitters
- obvious pump/valve alarms

### 2. Verify source/solution status

When required, confirm:
- correct tank/source
- pH/EC record
- batch/mix identity
- release/authorization status

### 3. Execute the supplied event

Follow the defined procedure rather than adjusting from memory.

For manual irrigation:
- apply to the assigned plants/containers
- maintain consistent method
- avoid runoff/spillage beyond procedure
- verify completion

For automated irrigation:
- confirm correct zone/program
- observe system start
- verify actual delivery at representative points
- check alarms or obvious failures

### 4. Verify delivery

Do not assume a timer or controller command means every plant received water.

Check representative points for:
- emitter flow
- leaks
- dry containers
- flooded containers
- pressure/zone issue indicators

### 5. Observe root-zone response

Use the facility's observation method:
- container weight
- moisture sensor
- visual/tactile media observation where appropriate
- drainage/runoff observation

The technician should notice when a zone behaves differently from expectation.

### 6. Understand dryback operationally

Dryback = reduction in root-zone water content between irrigations.

Key Technician I ideas:
- it is a trajectory over time
- one moisture reading is not the trajectory
- plant size, environment, roots, container and media change water use
- excessive saturation and excessive drying can both create risk
- the useful range depends on substrate/crop context

Do not assume “24 hours since last watering” means the same root-zone condition every day.

### 7. Document the event

Record what the facility requires, such as:
- date/time
- room/zone
- work-order/event ID
- source/tank
- volume/duration
- pH/EC when required
- delivery verification
- runoff/drain observation
- abnormal condition
- action/escalation

## Worked example 1 — Controller says complete, zone remains dry

**Weak response:** mark the event complete because the software did.

**Better response:** verify representative emitters/containers, document the delivery failure and escalate the affected zone.

## Worked example 2 — One blocked emitter

A single container remains much drier than neighboring containers.

**Response:** verify the emitter/line, correct within authorization or flag the equipment issue, document the affected plant/container and avoid changing the entire room program for one local failure.

## Worked example 3 — Repeated fast dryback

Containers that previously reached the supplied next-irrigation condition in two days now do so in one day as canopy demand increases.

**Technician response:** document the changed trajectory and escalate for scheduling review rather than assuming the old interval remains correct.

## Worked example 4 — Prolonged saturation

A zone remains saturated long after other zones begin drying.

**Response:** document the pattern, inspect for delivery/drainage issues within scope and escalate rather than adding another event automatically.

## Worked example 5 — Rising EC with deeper dryback

Repeated root-zone EC rises while the zone is drying farther between events.

**Technician response:** preserve both trends and escalate them together. Do not treat EC as independent of water removal/root-zone concentration.

## Worked example 6 — Leak creates false completion

The system ran for the expected duration, but a line leak diverted water.

**Lesson:** command duration is not equivalent to confirmed delivery.

## Common Technician I mistakes

- irrigating the wrong zone
- trusting the controller without checking delivery
- using elapsed time as the only dryback indicator
- changing schedule after one odd container
- ignoring leaks because plants still received some water
- marking event complete before checking representative delivery
- comparing moisture observations made with different methods
- failing to record local emitter failures
- applying another event to a saturated zone because the schedule says so without following exception procedure

## Guided practice 1 — Work-order check

Given an irrigation work order, identify:
- crop/zone
- source
- event parameters
- required measurements
- verification points
- completion record
- escalation trigger

## Guided practice 2 — Delivery map

A room map shows 24 emitters. Four containers in one line remain dry. Determine whether the pattern suggests isolated emitter failures or a shared line/zone issue.

## Guided practice 3 — Dryback curve

Review repeated container-weight or moisture data. Identify:
- irrigation point
- early drain period
- drying trajectory
- changed demand
- unusually wet/dry container

## Guided practice 4 — Controller versus crop

Compare controller logs with actual root-zone observations and identify where “event executed” does not equal “event delivered correctly.”

## Decision scenarios

1. One emitter blocked: local verification/correction/escalation.
2. Entire zone dry: check shared delivery path and escalate promptly.
3. Zone remains saturated: do not blindly add another event.
4. Leak during irrigation: stop/control within procedure and preserve affected scope.
5. Work order and controller zone disagree: do not guess; resolve identity before running event.
6. Dryback accelerates over several days: document trend for scheduling review.
7. One container differs from room: inspect local cause before room-wide change.
8. Root-zone EC and dryback trend rise together: document both and escalate context.
