# SOP Package Review Workflow

All 17 formerly planned THC-GROW targets now have controlled repository draft packages. This workflow governs what happens next.

## Review layers

1. **Machine structural QA** — package manifest exists, evidence plan exists, source IDs resolve, SOP/learner/handoff/records files exist, blocked release state is intact, and deterministic tests pass on the exact commit.
2. **Scientific/technical review** — claims, boundaries, reused course material, and source interpretation are checked against the exact package version.
3. **Safety/legal/engineering review** — applied only where the package crosses chemical, pesticide, worker-safety, electrical/HVAC/plumbing, laboratory, regulated-product, or other jurisdiction/facility controls.
4. **Accessibility/manual learner review** — rendered SOP/guide/forms are checked for readability, keyboard/screen-reader use where applicable, responsive layout, print usability, table/header clarity, and accessible alternatives.
5. **Facility/method validation** — local targets, instruments, layouts, sampling methods, acceptance criteria, products, equipment and workflows are demonstrated under actual intended conditions where required.
6. **Independent release review** — verifies that all prerequisite evidence is complete for the exact version and records the explicit release decision.

## Fail-closed rule

Draft creation is not release. Owner approval of the educational concept does not substitute for measured field/method evidence, rendered accessibility evidence, legal applicability, or safety/engineering qualification where those are part of the package.

Any substantive change to claims, procedures, acceptance criteria, records, or authority boundaries reopens the affected review layers.
