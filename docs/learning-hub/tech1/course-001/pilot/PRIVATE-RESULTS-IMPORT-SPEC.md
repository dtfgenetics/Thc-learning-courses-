# Course 1 Private Pilot Results Import Specification

This document defines the private response-level input accepted by `scripts/build-pilot-evidence-from-results.mjs`.

## Privacy boundary

The input file is a temporary/private analysis artifact. **Do not commit it to GitHub.** The repository may receive only de-identified aggregate pilot-evidence records generated by the script.

Use pseudonymous `participantId` values that cannot be directly reverse-mapped from repository content. Do not include learner names, emails, employee numbers, disability information, medical information, or free-text personal details.

## JSON shape

```json
{
  "cohortId": "TECH1-C1-PILOT-01",
  "analystId": "ANALYST-001",
  "completedAt": "2026-09-30T20:00:00Z",
  "responses": [
    {
      "participantId": "P001",
      "itemId": "ITEM-LH-TECH1-001-M01-001",
      "itemVersion": 1,
      "correct": true,
      "omitted": false,
      "selectedChoiceIndex": 2,
      "responseTimeSeconds": 41.8,
      "totalScore": 0.78,
      "responseTimeAnomaly": false
    }
  ]
}
```

## Required top-level fields

- `cohortId` — non-identifying cohort identifier.
- `analystId` — stable analyst/reviewer identifier.
- `responses` — non-empty array of response rows.
- `completedAt` — required when the generated evidence will be marked complete; use an actual completion timestamp.

## Response-row rules

Each row must contain:

- `participantId` — pseudonymous ID;
- `itemId` — exact current Course 1 item ID;
- `itemVersion` — exact item version;
- `correct` — Boolean scoring result;
- `selectedChoiceIndex` — zero-based selected option or `null` for an omission;
- `responseTimeSeconds` — non-negative numeric response time;
- `totalScore` — participant total assessment score normalized to 0–1 for discrimination analysis.

Optional fields:

- `omitted` — Boolean, recommended;
- `responseTimeAnomaly` — Boolean determined by the controlled analysis rule used for the cohort.

## Version control rule

Never combine responses from different item versions under one item-version record. If an item is revised after pilot review, the changed version requires new evidence.

## Aggregation

Preview without writing:

```bash
node scripts/build-pilot-evidence-from-results.mjs --input <private-results.json>
```

Generate draft aggregate evidence:

```bash
node scripts/build-pilot-evidence-from-results.mjs --input <private-results.json> --write
```

Generate complete aggregate records only after data QA is complete:

```bash
node scripts/build-pilot-evidence-from-results.mjs --input <private-results.json> --complete --write
```

A structurally complete aggregate record is not the same as decision-ready evidence. Course 1 decision readiness is evaluated against `PILOTPLAN-LH-TECH1-001` and `PILOT-DECISION-RULES.md`.
