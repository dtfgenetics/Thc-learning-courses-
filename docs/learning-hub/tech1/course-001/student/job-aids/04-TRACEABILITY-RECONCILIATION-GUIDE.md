# Job Aid 4 — Traceability, Event Genealogy and Reconciliation Quick Reference

**Use for:** movement, split/merge events, relabeling, samples, harvest containers, waste/disposition, downtime records and physical-vs-record mismatches.  
**Course objectives:** `LO-LH-TECH1-001-06`, `LO-LH-TECH1-001-07`, `LO-LH-TECH1-001-08`  
**Workbook practice:** Activities 4, 8 and 10

> Use the current site/jurisdiction workflow and approved software or paper process. This guide teaches vendor-neutral identity/event logic; it does not substitute for jurisdiction-specific seed-to-sale rules.

## Reconstructable event rule

A useful traceability event should let another qualified person answer:

**WHAT → WHERE → WHEN → WHY/PROCESS → WHO/SYSTEM → INPUT/OUTPUT RELATIONSHIP**

Capture quantity/count where the workflow requires it.

## Before a movement or transformation

1. Verify physical identity against the controlled record.
2. Confirm source location/state.
3. Confirm intended destination/new state.
4. Check holds, restrictions or unresolved discrepancies.
5. Verify whether the event creates a new identifier.
6. Preserve the relationship between old and new identifiers.
7. Record the event when it actually occurs using the approved process.
8. Reconcile the final physical state with the record.

## High-risk identity transitions

Slow down when material is:

- divided into multiple outputs;
- combined from multiple inputs;
- transplanted or moved between rooms;
- relabeled or assigned a new container/batch/lot identity;
- sampled;
- harvested;
- converted to waste;
- transferred between paper and digital systems;
- recorded after system downtime.

A new identifier should extend genealogy—not erase the prior relationship.

## Split/merge genealogy check

For a **split**, record:

**source ID → event → output ID A + output ID B + …**

For a **merge**, record:

**input ID A + input ID B + … → event → resulting output ID**

If a required relationship cannot be reconstructed, preserve the gap and escalate. Do not invent a source, quantity or identifier to make the chain look complete.

## Reconciliation workflow

1. Compare the physical state with the controlled record.
2. Recount/recheck only as allowed by the approved procedure.
3. Preserve the original discrepancy and original record history.
4. Separate confirmed facts from possible explanations.
5. Check the immediately preceding event(s) for identity, location, quantity and timing.
6. Make corrections only through the approved correction process.
7. Escalate anything still unresolved.
8. Keep affected movement/disposition controlled until the supplied procedure allows release.

## Strong vs weak response

**Weak:** “System says 48, physical count is 47, so I changed the system to 47.”

**Strong:** “Controlled record shows 48 units; physical recount confirms 47. I preserved the 48-unit record, documented the 47-unit physical count and time, checked the last authorized movement event, and escalated the unresolved one-unit discrepancy without forcing either side to match.”

Why the strong response is better: it preserves evidence and allows the discrepancy to be investigated instead of hiding it with a premature correction.

## Waste/disposition reminder

Waste or other disposition does not end traceability until the applicable controlled process is complete. Preserve:

- source identity;
- amount/count where required;
- time/location;
- disposition status;
- who/system recorded it;
- any required witness/authorization under the local process;
- relationship to the source material.

Do not use this course to infer one universal destruction method.

## Downtime rule

If the primary digital system is unavailable, use the approved downtime method. Preserve at minimum the event time, physical identity, source/destination, quantity/count where required, responsible person/system and enough context to reconcile later.

When the system returns, reconcile the downtime record—do not rewrite the original event as though it occurred later.

## Documentation formula

**event time + object/material ID + source + destination/new state + quantity/count + input/output relationship + recorder/system + discrepancy/status + escalation**

## Handoff trigger

Include unresolved identity mismatch, count difference, pending correction, unposted downtime event, hold/disposition status or genealogy gap in the shift handoff.

## Pocket use

Use the sequence:

**IDENTIFY → RECORD EVENT → LINK INPUT/OUTPUT → VERIFY PHYSICAL STATE → RECONCILE → ESCALATE GAPS**

When physical reality and the record disagree, preserve both until the authorized process resolves the difference.
